# 具名核验协议改造与固定小集对照

2026-09-07。服务 `611a2f9`，评测器 `c1bca67`，冻结工作区 `18555d7`。改造已实现；部署默认仍为 compact，named 显式可选。没有重跑100题，也没有更改旧分数。

## 改造边界

`MEMORY_VERIFICATION_FORMAT=named` 将模型核验协议改为四组具名对象，并在输入中提供消息、事实、操作、替换检查及来源的明确 ID。持久化 memory_id 与本轮 fact_id 分开，来源 ID 绑定具体事实。适配器逐项解码后复用原有证据、覆盖度、来源与删除授权校验；不改变数据库和对外 HTTP 接口。

共享语义要求保持不变；旧 compact 的来源覆盖提示经逐字比较未变化。具名格式的未知引用、缺项、重复项、跨消息来源及额外字段仍不能签发成功证书；有效否定会保留，即使兄弟项损坏也不会重新采样至通过。格式改变使旧核验缓存失效。模型路由、并发、请求截止、运输重试及语义修复上限均未增加。

本次只替换核验协议；抽取、删除分类和修复补丁的格式未改，尚未实现新的定向缺项补齐或失败隔离机制。结构损坏 JSON 仍不猜测补全判定。

## 判断与下一步

本轮新协议服务token少约13.9%，输出token却增加约21.8%。较少的调用来自一次内容修复及其重验的差异：旧组首次抽取遗漏平板未售状态，核验发现后触发修复；新组首次抽取已经包含未售状态。抽取本身未改但模型输出有波动，因此不能把节省直接归因于核验协议。

两组结构错误均为零，本次不能证明新协议减少了长背景结构失败。6/10与5/10只是单次暴露小集的原始机器分数；Answer/Judge仍有既有证据校准问题，人工标签为0，未做分数覆盖。整轮耗时也没有改善，不能把写入耗时下降当作端到端加速。

结论：具名协议功能与校验边界已完成，暂不改变默认部署配置、不追加样本或重复次数。若后续开展长背景验证，使用独立冻结配置和新campaign，重点比较核验结构失败、完整背景完成率、正确性及单位成功写入成本，再决定是否将 named 设为默认。
