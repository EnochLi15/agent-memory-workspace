# V1 阻塞修复进展（未封版）

更新：2026-09-07。当前仍在 P0-1；本报告不代表 V1 完成，也不替换中断评测的原始结果。19 次终止写入的逐项原因、处理决定与证据见 [机器可读清单](v1-blocker-followup.json)。

## 已完成的修复与验证

- HTTP 200 的未完成 SSE 流携带无状态码错误时，按受限的传输分类进入原有有界恢复；鉴权、非法请求、拒绝、未知明确错误类型、完成后的错误仍不可重试。完整 HTTP 回归验证重放、唯一提交和重复回执。
- `No, don't track…` 和 `…, so no need to track…` 能进入遗忘授权判断；引用、条件句、否定删除保持拒绝。
- 食谱等文档标题不再被误认为真实参与者。原失败现场 `Ingredients:` 下的 `Remove from heat` 不再触发遗忘义务。
- source-first 抽取失败直接保留原始错误类别，避免先离线降级、再被“缺少来源覆盖”掩盖。
- 数字来源偏移出错时，仅在同一条消息中存在唯一、完全一致的引文才重新定位；重复引文、跨消息借用、模糊匹配仍不接受。
- 抽取和核验共用图片元数据、礼貌性赞许及未来意图的证据边界。四个已曝光最终提案的真实模型复核中，三个没有事实拒绝或缺失；另一个消除了图片误拒绝，但产生了新的内容覆盖争议。独立负例确认不能从图片推断个人偏好。这是核验单阶段证据，不能作为完整写入成功率。

服务修复提交 `4ba5891` 已推送私密仓库。构建通过，全套 **347/347** 测试通过：[原始输出](v1-service-regression-02.txt)。运行身份与托管测试 **12/12** 通过，包括原实验身份校验、父进程退出、SIGTERM、SIGKILL 后失活识别、启动失败、并发争抢和退出码记录。

## 外部故障与正确拒绝

一次新的 D25 单段准备中，来源路由成功，后续模型连接失败，准备以 `EXTRACTION_UNAVAILABLE` 结束；没有执行提交。随后的 [独立 HTTP 诊断](round2-fresh-failed-add-mjLB6H.json) 已成功：首次90.1秒返回恢复待续，相同请求第二次37.4秒返回200；仅增加一个版本并保存唯一回执，原数据库未改变。该诊断使用隔离副本和明确的新诊断身份，不补写旧评测成绩。不能因为修复了代码缺陷就声称网关已经稳定。

四次“恢复不可继续”与系统日志中 920 秒合盖睡眠、547 秒维护睡眠的时间窗口吻合，超过五分钟内存缓存有效期。原 runner 后续消失的直接原因仍未知，不能把合盖证据当作退出原因已经查明。

C27 的模型擦除计划删除了关联事实，却保留其原文证据；服务一致性检查拒绝了事务。涉及错误目标、未经支持的事实或不一致擦除的拒绝继续保留，不通过放松校验提高成功率。第一人称“不打算自行追踪”是否构成系统删除授权仍有语义歧义，本版不将它无条件授权。
