## 修复内容

| 问题 | 根因与修复 | 保留的边界 |
| --- | --- | --- |
| 历史追踪遗漏被更正的旧金额 | 普通有效事实过滤同时作用于事件的旧值，导致“哪些消息最初说明、后来更正”看不到原始说法。真实旧记录又是 `quoted` 转述，初版额外过滤仍把它挡在候选生成前。最终补丁对明确追问历史消息的查询保留被更正的转述，事件明确标明它不是有效或当前事实。 | 当前值查询继续排除旧值；已遗忘内容、依赖已遗忘内容的派生事实不能恢复。 |
| “上周”被展开成有歧义的日期边界 | 检索输出曾把内部用于排序的周起止日期呈现为事件发生区间。现在保留“锚点日期之前一周”和原始时间词，明确周级精度，不输出该归一化起始日作为 valid-from。省略空 scope 字段。 | 内部时间归一化与排序保持一致；明确的“昨天”等日级表达继续解析；不修改 Answer/Judge 提示词。 |
| JSON 键名弯引号导致整次抽取降级 | 模型真实输出把三处 `message_index` 键用 U+201C/U+201D 包围。只在 JSON 字符串外、合法键名位置修正成标准引号，并记录修复类型和数量。 | 不修改字符串值、false 判定，不补字段、截断输出或语义内容；结构、引用、独立语义验证继续执行。 |
| HTTP 400 无法定位、担心降级持续 | 增加经过白名单限制的供应商错误码审计。原请求精确重放得到 400/1301；集成测试确认一次拒绝不影响后续正常抽取。 | 不对 400 盲目重试，不变更评测输入；已成功降级提交的同请求保留幂等回执，不偷偷重新生成并改写历史。 |

## 原始失败重放

- JSON：固定原模型输出，经真实 SDK/SSE 聚合路径修正 3 处键名引号；6 个消息组、5 条事实通过源引用协议解码、结构和原文引用检查，远程模型调用为 0。这不是对其语义正确性的重新裁决，正常入库仍必须经过独立验证。
- HTTP 400：原 system/input 和 GLM-5.2 路由保持一致，只进行一次精确重放，约 1.51 秒返回 `provider_error_code=1301`，尚未开始响应流。智谱将该码定义为可能包含不安全或敏感内容的拦截。[智谱官方错误码](https://docs.bigmodel.cn/cn/api/api-code)
- 原失败没有保存供应商业务码，因此新证据能确认本次精确输入重放的拒绝类型，不能倒填原日志或断定具体哪段内容触发。
- 明细：[恢复诊断 JSON](priority-quality-recovery-20260908.json)。原失败记录和候选诊断分别保存，不覆盖旧运行。
