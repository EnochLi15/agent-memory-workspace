# 固定预算质量对照

本文件定义第二轮E2/E3的开发集对照；它不是已完成的实验结果。使用已经曝光的开发数据，不能将其称为新保留集。完整E0–E5、三个完整重复、新数据评测和最终交付范围不变。

## 冻结参数

配置文件为[round2-quality.json](../configs/round2-quality.json)。提取使用gpt-5.4-mini，核验/修复使用gpt-5.5，reasoning low；核验为compact，最多两轮提案补丁、请求内通过记录复用。模型预算90秒，写入115秒、检索55秒。配置是待评估候选，不是生产默认。

本地nomic-embed-text固定digest及768维；候选最多200，重排输入最多80；最终最多32条/6000 token。Answer和普通Judge固定gpt-5.4-mini，Answer提示词及1800输出预算不变。普通Judge仍是原协议，E0独立审计作为另外一项报告，不回填历史分数。

四组写入、生命周期、时间规范化完全相同；事件投影和关系扩展均关闭，单独留给E4/E5。facts仍保留事实关联的引文上下文，不能描述成“完全不含原文”。候选来源的比较不改变最终证据预算。

首次灌入必须全段成功，才允许其它纯检索配置通过原request_id重放复用幂等回执。执行器先核对数据hash、服务/评测commit及干净源码、写入模型/表示/修复配置；不匹配即拒绝启动复用。灌入失败时保留全部计划题及service_error，不从配对分母删除失败背景，也不将失败快照拿来计算检索收益。新的独立重复使用新的campaign/命名空间，不通过复用一次灌入冒充三个完整重复。

启动命令示例（根目录、Node24在PATH）：

```sh
python3 scripts/run-experiment.py --spec configs/round2-quality.json --campaign round2-quality-dev-441cc48-r1 --profile facts --benchmark memops --split dev --port 8096 --concurrency 2
```

成功灌入后，sources/rerank/coverage分别使用同campaign和`--reuse-ingestion facts`。未成功时应先报告写入失败及阶段归因，不能靠删题生成对照分数。不得覆盖已存在的campaign/profile输出。

## 每个结论需要的证据

- 写入：全部计划chunk、成功/拒绝/降级、实际模型路由与调用量；部分前缀成功不等于整个背景已完成。
- 检索：按题比较事实/原文候选、重排和预算淘汰；来源ID命中只作诊断，不能代替答案正确性。
- 生命周期：旧值泄漏、误遗忘、来源残留单独检查；不能用总体正确率抵消错误删除。
- 问答：固定Answer/Judge的逐题结果和失败分母；按背景汇总配对差异。开发集背景很少，不宣称统计上可靠的泛化提升。
- 成本：输入/输出token、模型调用数、延迟和并行负载。核验器单独调用的节省不能外推为全管线同等节省。

正式新数据在四个失败前缀及变体通过后，刷新曝光审计、冻结选择规则，再选择未记录曝光背景。配置调整只依据开发材料；三个完整重复及新集结果均完成后再决定部署。

## v3删除范围候选配置

`configs/round2-quality-erasure.json`在strict候选上增加`MEMORY_ERASURE_BINDING=true`，其它四级检索参数保持一致。它改变写入过程及存储表示，必须新建v3目录，不允许与旧strict/json_object的灌入混合比较。语义范围判定使用既定核验模型，仍在原模型总预算内，不能独立多给90秒。

在B05原失败提案上的单独范围判定为5.8秒；一次新完整失败片段prepare为75.1秒，其中范围阶段3.3秒。前者固定了原提取，后者使用新的模型抽取，两者不能作端到端延迟差分。原始前缀和完整背景也不能混称：复现至旧失败点通过以后，仍须继续其余会话和全部计划问题。
