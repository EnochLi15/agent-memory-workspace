## 当前运行与冻结边界

生产运行源码冻结在 service `910b3dd`。之后的 service 提交只修正测试准备步骤和 U0/U1 对照 HTTP 适配器，生产 `src` Git tree 完全一致；见 `reports/runtime-equivalence-v6.json`。最终保留集为 `holdout-v2-U3-*`，完整候选开发对照为 `dev-v6`，修正重试行为后的原版/机械拆分对照为 `baseline-v7`。

独立的合成容器 smoke 发现同一句更新与遗忘混合时，离线提取错误丢弃剩余子句。修复覆盖同 chunk 新事实撤销和推断依赖可见性；没有依据保留集答案调参。旧 holdout-v1 被明确标记为 superseded，保留原始产物。

干净克隆第一次验证中，80ms 请求超时测试把 Fastify 首次路由启动算入 250ms 的请求计时断言；服务仍返回预期 503。测试显式等待 ready 后，隔离重测及 35+8 全套测试通过，运行代码未改变。初次失败日志保留，不把该次克隆直接声明为全项通过。

U0/U1 原版适配器此前未合并执行中的相同 request_id，超时重试产生并发重复灌入。现有请求共享同一执行 Promise，按用户顺序灌入，成功后保存进程内回执；上游算法、提示词、方法体均不变。旧 dev-v6 U0/U1 已标记为 superseded，新 baseline-v7 使用全新命名空间。

## 结果使用边界

正式平台 Answer、500+500 选择器与 MemOps 精确二值映射未提供；本项目结果属于明确配置的公开复现，不能当作正式平台成绩。本地 Qwen3:14b 为 Q4_K_M 量化版，embedding 为已安装的 nomic-embed-text 768维，模型 digest 已记录。

早期 dev-v1–v4 的 MemOps 题号重复，不能与修复后的题数或准确率直接比较。修复后的公开归一化数据包含 LoCoMo 10个样本/1382题、MemOps 403个样本/4012个唯一题实例。开发集各30题，保留集各500题；完整对话噪声保留。

远端生成/判分失败保留在计划分母；错误阶段与共同完成判分的子集另行报告。来源 ID 覆盖率只是证据诊断，不等于语义支持率。全局哈希遗忘匹配较保守，不能据有限测试声称任意同值场景都不会误删。
