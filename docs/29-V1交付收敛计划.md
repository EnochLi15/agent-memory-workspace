## 交付目标

交付一个从干净环境可安装、可启动、可演示、可评测、可定位故障并可升级的项目。第一版保留赛题的三个 HTTP 接口、同步写入、用户隔离、记忆提取/存储/召回/更新/遗忘和基础时间处理。以可核验的工程完成度和真实效果报告验收，不承诺未测得的准确率或外部模型可用性。

原1000题评测已中断：LoCoMo 83/500；MemOps还有348题无结果。该轮永久保留为中断记录，不拼接成完整新成绩。历史331/1000保留。来源：[中断报告](../reports/round2-full-98c12e5-interrupted.md)。

## 一条主线，五个可验收工作包

### P0-1：修复阻塞，明确失败边界

实施起点为service `98c12e5`、eval `11da2a6`，在新候选提交中改动，不篡改旧实验身份。

- 对已保存19次终止写入逐项建立“预期行为—实际行为—原因—回归证据”映射，复用现有测试目录和保存现场。按错误类别修复，不按题号、姓名或答案特判。
- 首先处理缺状态码流错误的分类和传播、抽取/核验的可记忆性口径冲突、来源覆盖与擦除计划不一致、4次恢复不可继续的真实触发原因。保留对无来源事实、错误目标和非法删除的拒绝。
- 将模型预算与HTTP截止时间、可重试传输错误与语义拒绝分开。仍使用原请求ID和载荷，仍有次数/时间上限；不扩大重试直到成功，不提交未经核验的半成品。
- 在现有运行入口和部署方式中处理长任务托管，保存runner退出码/可观测终止信息，识别失活进程和陈旧manifest。用不消耗模型的验证覆盖超过本轮约两小时的运行窗口，以及父会话结束、正常停止和异常退出。SIGKILL等无法由子进程自报的情况由外部观察记录，取不到原因时保留unknown。
- 恢复边界明确：已提交请求重试返回唯一回执；未提交事务无半状态；同进程可继续的请求按现有有界机制恢复；进程重启丢失模型响应缓存时明确终止，不假装支持跨进程续跑。不为本版扩建持久化工作流。

完成证据：适用的服务/评测器测试通过；新增回归先复现再修复；每个已确认P0有原因及验证结果；无已知的串用户、重复提交、漏遗忘、误删邻居、错误成功或长任务无状态退出缺陷。正常输入与应拒绝输入分别验收，不能要求所有历史拒绝都改成成功。

### P0-2：整理唯一发布配置与交接入口

- 同步`.env.example`、Compose、Makefile和服务配置，明确开发、增强部署和离线运行的命令、模型前置条件及数据目录。增强模式不能静默变成离线成功。
- 保持`/add`成功立即可检索，服务不生成最终答案。最终证据上限保持32条/6000估算token；请求截止仍为add 115秒、search 55秒，落在赛题120/60秒约束内。
- 用已有结构化日志区分模型通信、语义核验、存储、请求超时和评测进程退出。普通日志记录请求关联、阶段、耗时、错误码和恢复结果；私有模型原文追踪单独开启，凭据不进入日志或交付包。
- README明确实际入口、已验证平台和当前版本，不继续把旧8088部署、旧测试数或331/1000当成新版本现状。提供一次完整写入/查询/更新/遗忘演示和故障排查路径。
- 明确离线方案的支持范围并独立验证；无法安全执行的复杂语义操作应明确失败，不能把离线模式标成增强模式等价替代。

完成证据：独立干净递归克隆可按文档构建；service无需eval运行时代码即可启动；契约测试通过；正常停止保留数据，重启后已提交记忆与遗忘状态不变；演示命令均由实际执行验证。

## 如何保持可演进

| 稳定边界 | 后续变化方式 |
| --- | --- |
| HTTP契约 | 保持现有三个接口与权威schema；内部重构必须通过相同黑盒测试 |
| 模型适配 | 基于现有Models模块替换provider/model；统一错误、预算和响应校验，不散落调用 |
| 准备与提交 | 提案准备不直接写库，事务提交负责一致性；内部类型和负例回归固定行为 |
| 检索与证据预算 | 新召回/排序组件通过配置进入候选；保留当前简单路径和同预算回归 |
| 数据格式 | 版本检查、升级/重建说明、备份与回退成对验证；不默认为旧数据向前兼容 |
| 评测 | eval始终只用HTTP；同题同预算对照，完整分母、错误和来源身份保留 |
| CI与维护 | 复用两功能仓库现有CI做构建、类型、单元/契约检查；真实模型验收单独留证，不要求每次提交都跑1000题 |

不为“可演进”提前增加通用抽象。每个后续改动都要求问题、最小改动、相关回归和结果差异；更新完成边界后再发布补丁或次版本。

## 排序与停止扩张规则

1. 先修P0-1已确认的功能阻塞。无模型长任务验证后台运行期间，并行完成P0-2部署和配置验证，避免纯等待；门槛不减少。修复后形成可验收候选再运行固定小集。
2. 模型、算法、预算保持单一主配置，不并行试多套架构。只针对已确认的交付阻塞修复；未知问题先保存证据，不继续堆防御分支。
3. 小集通过后就转全量和封版，不继续扩大研究矩阵。完整评测只承担一次冻结版本的测量，不承担边跑边调参。
4. 任一门槛失败，只回到该工作包修复其原因。不能靠去掉遗忘、隔离、原子性、失败分母或审计来“加速完成”。尚未通过的版本维持RC状态。
5. 正式版后再排准确率优化、更多未曝光验证、统计重复、长期跨进程恢复和更大规模存储。后续清单保持有限，不阻塞已经验收的首版。
