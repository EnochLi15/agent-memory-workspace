## E1 第一批实现

- 独立指令片段模块保留原始偏移，识别直接遗忘和停止存储表达，区分否定、引用、条件与转述；一段引语不再否定其它句子的直接请求。
- 对识别出的每条遗忘指令检查操作覆盖。空模型结果、只覆盖第一条指令或用整段引用冒充多个指令覆盖时，进入有界修复/确定性恢复；不能解析的操作失败，不返回空操作成功。
- `new:N` 引用由服务生成持久ID，并检查新事实的来源先于操作或依赖事实。同消息中的未来事实也不能通过空ID的属性选择器被提前删除。
- 操作绑定检查主体与范围。同值但不同明确scope的记录不再被全局值匹配连带删除；混合引用不能携带已删除上下文。重复的已删除属性可证明为no-op，未知新值不能借此通过。
- 修复额外发现：提取事实的对象展开曾把临时 `sources` 数组写入数据库，该字段不在 `Fact` 类型中，遗忘时未被清理。现在提取阶段不复制该字段，存储写入也移除它；已遗忘事实清空原始时间表达。新版本须使用新数据目录，旧数据未在原地迁移。
- 评测器将新增语义错误码列为不可按传输故障重试，失败仍留在完整计划分母。

验证：新增10组回归在实现前的首批8组全部失败，修改后服务全部47项测试通过（含真实SIGKILL事务回滚、HTTP、幂等、隔离和重启）；评测器8项Node及2项Python测试通过。日志见 [服务](../reports/round2-E1-service-tests.txt)、[评测器](../reports/round2-eval-tests.txt)。这些是确定性桩和本地HTTP验证，尚不是远程模型质量评测。

尚未完成E1：完整的结构化语义核验与定向修复、候选扩展、4个真实失败前缀复现、来源位置持久化与细粒度片段可见性、并发重排删除的新版本验证。当前规则只覆盖已定义的指令表达，不能宣称任意自然语言删除意图均不丢失。E0、E2–E5及最终交付仍需继续。

源码核查修正：基线Worker在重排开启时已把内部预算放大到最多64条/18000 token，但数量仍受请求top_k约束；Engine最终裁到32条/6000 token。因此下一步要真正分离候选召回与最终打包，不能把预算放大本身算作新改进。

## E2/E3 核心管线与 E0 阶段诊断

- 事实持久化原始来源位置；新增 `passages` 与独立FTS表。按原文句子切片并限制每片900字符，保留说话人、外部来源ID和UTF-16位置。原文与事实一起调用本地embedding，分路语义/词法召回；原文不是摘要或最终答案。
- 遗忘事务按照来源区间裁去对应内容，同时清理向量与FTS。片段裁剪后不沿用旧向量，剩余独立细节仍可词法召回。未提取的旧值重放也受标记检查；保留事实、原文片段和依赖可见性一起过滤。原文引用不能通过历史查询恢复已遗忘值。
- 新格式明确标记为 `dual-source-v1` 或 `facts-only-v1`；切换表示需要新目录和重新灌入，删除-only请求也不能绕过检查。不会为每次写入重建未变化原文的FTS。
- `collectCandidates → compactCandidates → packEvidence` 已分离。内部候选池默认200，重排最多80，均不受请求top_k限制；只在最后扩展来源上下文并执行返回数量/token预算。列表/轨迹选择偏好新条目和新来源，公开score仍降序。模型给0分或未选择的候选不再挤占最终预算。
- Worker在一个任务内检查版本、重新召回并打包；重排期间发生修改时，丢弃过时排序，按新版本可见性返回。没有增加HTTP路由、请求gold字段或最终答案生成逻辑。
- 可选 `MEMORY_RETRIEVAL_AUDIT` 输出各路ID、候选池、重排选择、预算/数量淘汰和最终选择。查询、租户、外部来源ID只记录hash，不记录证据正文。独立 `eval/python/diagnose_retrieval_stages.py` 再与gold来源ID比较；没有标注、多条同键trace或trace缺失单列，不假装召回失败。诊断仍只是来源ID丢失，不是语义蕴含或生命周期过滤错误的证明。
- 补强重复删除测试后，发现原操作提示事实可能被误当作被删除属性。现排除该候选，重复删除还要匹配已有删除标记及边界，不能以“某目标已删除”证明任意新值请求已经完成。

## E4 时间与事件核心实现

- 按消息解析并跨chunk保留明确会话日期；普通时间戳随新消息推进。事件日期与消息观察日期分开，支持明确日/月/年和部分相对时间、周区间；月份不补造具体日，合成排序时间不能作为相对日期锚点。歧义范围、多个锚点或不支持的表达保留未解析。
- 新格式升至 `dual-source-v2` / `facts-only-v2`，必须新目录重新灌入。单值状态比较精度区间；月份内的未知更新边界不强选某个状态。过去事件、将来计划、错误纠正与真实历史分开处理。
- 在原子事务中记录 remember/update/correct/retract/forget/restore/reflection 事件，持久化只存闭集类别、顺序、来源和状态ID，不复制旧值。查询按现有状态与依赖可见性动态投影，删除后事件不携带已忘值；操作发生时间不继承其目标所描述的历史日期。`MEMORY_EVENT_VIEW` 控制事件召回。
- 修复 `Correction:`、`Remember again:` 等指令前缀被当成人名的问题。重新记忆必须绑定实际用户属性与删除标记，不能靠错误主体绕过授权。
- 时间证据单独显示事件日期或月份，保留原文供核验；重排紧凑输入同样带时间说明。普通Answer提示词保持原哈希。
