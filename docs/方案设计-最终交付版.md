## 一、方案与架构合理性

### 1.1 总体架构

```
POST /add ──▶ Extractor（提取/指令识别/时间归一）
                │  能力故障 → 确定性降档方案（degraded 标记，§二）
                ▼
             VerificationSession（逐条证据核验：主体/否定/来源/独立性）
                ▼
             TenantStore.commit（单事务：facts + passages/FTS5 + 向量 + memory_events + 边界 marker + 幂等回执）
                ▼
             SQLite（每 user 一库，WAL，sourceFormat v2–v10 粘性）

POST /search ─▶ intent 意图路由（v2，1,544 题验证零误报）
                ▼
             多路召回（语义 / 词法 FTS5 / 实体 / 事件投影 / 关系扩展 / 原文回退）
                ▼
             仲裁重排（链乘数 + raw 降权 + 主体降权 + 题面候选梯 + temporal 加权）
                ▼
             packEvidence 呈现（T 模板包裹 / 时间锚前置 / 状态后缀 / 逐字支撑 / token 预算）
```

**双源表示**是存储层核心决策：结构化事实层（可仲裁、可作废、携带状态）与原文段落层（FTS5+向量，保逐字证据）同库同事务。检索时事实层优先（同键去重时事实胜出，§1.4），原文层兜底未抽取细节——直接服务 MemOps「泄漏=判失败」的口径。

### 1.2 记什么（提取）

**判定轴**（每条候选事实在入库前定型）：
- **主体**：用户自述 / 具名第三方（`Raj: ...` 前缀）/ 助手——助手建议与转述永不冒充用户事实（`quoted` 模态，检索不可见）；
- **模态**：confirmed / tentative（计划、未定） / hypothetical / quoted / inferred——tentative 永不覆盖 confirmed（防近因陷阱）；
- **基数**：single（可作废的属性值，如 current_city/door_code）vs multiple（爱好、经历）——只有 single 进入版本链仲裁；
- **谓词族**：propertyFamily 归并（city/city of residence → 同族），避免同义谓词裂解成假冲突。

**指令识别**：forget/correct/restore/update 祈使句 + 否定（"do not forget"）、引述（""forget it""）、条件（"if I change my mind"）、第三方转述四类否决条件；指令来源必须是人类用户发言。

**噪声过滤**：问候/纯提问/教学文本不入库；`experience` 桶需第一人称方成事实；对话标题、操作回显不进原文索引。

**无时间戳输入**（官方消息形态）：合成严格递增 ISO 排序标记（base = 已存最大观测时间 +60s/条），`time_basis='ordering'`；**合成标记不得充当日期锚**——"last year" 在无真实锚时解析为 unresolved，不发明日期。

### 1.3 怎么存（存储）

- **fact 模型**：subject/predicate/value/scope + 状态机 + 时间证据（event_time/valid_from/valid_to/transition_time）+ 溯源（source_ids/source_quotes/source_spans UTF-16 偏移）+ 依赖（depends_on，派生事实随支撑失效而作废）。
- **slot 版本链**：`canonical(subject)+propertyFamily(predicate)+canonical(scope)`——同槽 single 事实构成链，是更新/遗忘/仲裁的操作单元。
- **五态状态机**：active / conflicted（同效期双值，不猜） / superseded（旧值，携带 valid_to 与后继注记） / retracted（纠错撤回） / erased（遗忘，值与内容物理清空，留边界 marker）。
- **事件账本 memory_events**：remember/update/forget/reflect 事件只存 ID 引用、不复制值——轨迹类问题的证据来源，且遗忘后不残留旧值文本。
- **幂等与并发**：request_id 回执（同 ID 异载荷 409）；每 user 串行队列 + 修订号乐观并发；跨进程写续传 ledger（可选开启）。
- **表示演进粘性**：sourceFormat v2→v10 各能力（语义擦除/源擦除/语义转移/源路由/批处理/覆盖）随目录锁定，中途换表示要求新目录——保证评测目录内行为一致。
- **聚合卡（反思层，确定性）**：内容型 add 时，本 add 事实 + 跨会话快照按 canonical(主体)+谓词族+canonical(范围) 分组，≥2 个不同值的 multiple 族物化成一张 `reflection`/`inferred` 卡——值排序后**原样**嵌入单条证据（`[Aggregated pattern] user: hobby — hiking, photography, rock climbing (3 statements)`），每值一个代表 id 入 depends_on，值集变化时 supersedes 旧卡。一条机制同时服务 MemOps Reflect 汇总与 cat1 列表完备；遗忘成员值 → 卡随 depends_on 传递擦除。卡按**成员粒度**参与重放防御与擦除（卡的 source 并跨越全部成员消息，整卡吸收/连坐会过度脱敏无辜兄弟成员的原文），且完全不进入消息层记账（searchable/redact/原文改写均跳过 reflection 卡）；restore 的成员重新入库后，家族卡随下次内容 add 重建。离线/增强（含降档）双形态同样产出，不依赖模型。

### 1.4 怎么召回（检索）

**意图路由（intent v2）**：current / historical（used to、previously、what was … before） / trajectory（how did … change、walk me through、evolution 共现约束） / operation / list / temporal / as-of。正则在 LoCoMo refined + MemOps 全量 1,544 题上验证：轨迹/历史零误报，裸 before、in 20xx 等误路由形态已剔除。意图决定可见性（superseded 仅历史/轨迹/asOf 可见）与事件投影开启。

**多路召回**：语义（向量，同 embedding 空间校验）+ 词法（FTS5，中英混合分词）+ 实体 + 事件投影（operation/trajectory/history 意图）+ 两跳关系扩展 + 原文回退（段落层，仅当其链接事实可见）。

**仲裁重排**（本方案核心增量；基座混合分差 <3% 无排序信息）：
- 链乘数：当前值（有历史时）×3；tentative ×0.4、conflicted ×0.6 —— **相对分离**：仅当链上存在 confirmed 赢家才降权，无赢家时事实层保持可见（状态文案不丢失）；历史/轨迹意图下 superseded ×2.5、当前值 ×1.2（链序可读）；
- **raw 层全局 ×0.4**：原文段是兜底，同键孪生竞争时事实层（携带状态/时间/主体）必胜；
- **主体降权**：自指查询（my/I）下具名第三方 ×0.3，反之用户主体不抢占具名查询——压制 near-miss 干扰项（MemOps 最大干扰族）；
- **题面候选四级梯**：题面枚举（"which of these would you choose, 60143 or 60148"，或 options 字段）→ L1 精确等值/逐字包含 → 数字守卫（位数变体只能精确胜出）→ 短串守卫（≤3 词永不模糊）→ L4 长文重叠 ≥0.8；唯一精确命中者强制 rank-1，歧义不动排序；
- temporal 意图下带时间锚事实 ×1.4；
- **多源佐证（仅排序信号）**：conflict 态下同一值被 ≥2 条独立陈述复述 → 该值 ×1.5 相对加成并补注 `corroborated by N independent statements`——冲突状态**不自动消解**（两次回声不得凭计数翻转一次更正，防近因陷阱反例）。

**呈现定律**（证据文本形态，answer 模板直接消费）：
- 旧值旅行包裹：`Former current_city: "Seattle" (superseded; current current_city: "Boston"). Original statement: …`——答旧值必见新值，压「旧值率」；as-of 视图**不注入**后继（定点问题中后继是时间轴干扰物）；合成时间基不打印日期；
- 冲突显式：`[Conflicting statements recorded; no single current value]` + 状态后缀；
- 时间锚前置：`[2026-01-01 | user] ` 或 `[time: session order only] ` 引导内容，顺序阅读的答案模型先获得时间立足点；
- 逐字支撑：来源原文摘录（验证主体与否定），遗忘后的引用自动脱敏；
- top_k 截断 + 全局 token 预算 + 覆盖度打包（list/轨迹优先互异条目与新来源）。

### 1.5 更新与遗忘（对 MemOps 三子指标）

- **更新**：同槽新 confirmed 值 → 语义转移核验（v5+；不确定 → 双方 conflicted 保留）或日期裁定（overlap→conflict；先后→supersede + transition 窗口）。as-of 查询按日界回放。
- **遗忘**：三层——①事实擦除 + **边界 marker**（属性/值边界、允许值哈希白名单）；②**独立性豁免**：同句邻事实若能出示独立见证（不含被删值的从句）则保留——防「过遗忘」；③**源擦除**：原文区间切割（UTF-16 偏移），消息变 `[…]` 部分可检索；助手回声与未抽取复述同路径清洗——防「泄漏」。重放防御：精确旧值复述不能复活已遗忘材料（marker 匹配即吸收）；restore 需显式再授权且只放行新值。
- **子指标映射**：旧值率 ← T 模板 + tentative 不覆盖 + 冲突显式；泄漏 ← 事实/原文/事件/尾句四路径一致清洗 + 审计日志；过遗忘 ← 独立性豁免 + 邻句保留 + 值白名单。

### 1.6 与短期记忆的边界

本服务是**长期记忆服务**：只保存跨会话需要的事实、偏好、约定与事件。会话尾部（最近 10 条）仅作为提取语境（指代消解、时间锚接续），**不参与检索**；不做对话内 scratchpad、滚动总结或当前会话全文缓存——短记忆归调用方（评测机自带 full_conversation），边界即赛题"灌入历史→检索证据"的分工。

### 1.7 抗噪声（分层语义）

- **入库轴**：提取过滤（闲聊/问候/教学）+ 模态降格（tentative/hypothetical 不当 confirmed）+ 助手话语隔离；
- **召回轴**：干扰物四轴论——值轴（数字近邻守卫）、主体轴（第三方降权）、时间轴（intent 可见性 + asOf 去后继 + 合成基不造日期）、确认度轴（tentative/conflicted 乘数）；
- **误路由防御**：intent v2 的共现约束直接来自 1,544 题误报分析（裸 before 曾把现值题错路由到历史链）。

## 二、写入成功哲学（本版本核心取舍）

评测机**不重放失败的 add**：一次 5xx = 该样本全部后续题目丢失。据此：

| 故障类别 | 行为 |
|---|---|
| 能力故障（网络/超时/坏 JSON/模型宕机/核验通道不可达/分片不可达） | **降档提交**：确定性方案（擦除全候选带见证、转移全标 uncertain、离线正则抽取）+ `degraded` 审计标记；HTTP 200 保持可检索 |
| 语义拒绝（模型健康但认证"不确定/不独立"） | **不降级**，保持拒绝——过度擦除是另一种判失败 |
| 退休指令不可绑定（目标不存在/歧义） | **原子拒绝**（fail-closed）：HTTP 200 必须意味着指令生效，无声 no-op 等于欺骗调用方 |
| 写续传模式（交互式客户端） | 保持基座严格契约（degraded 拒绝、ledger 重放拒绝）；**评测部署关闭该模式** |

三条契约均由命名测试固化（operation-intent / retirement-effect / write-continuation 系列），是后续迭代的不可破坏边界。

## 三、工程质量与可部署性

- **启动（非交互）**：`docker compose up -d`（compose.yaml，env-file 注入配置，数据卷持久化，stop_grace 125s 覆盖 add 尾时）；或裸机 `set -a; . configs/release-offline.env; set +a; node service/dist/server.js`。Dockerfile 多阶段构建、非 root 用户、内置 healthcheck。
- **配置矩阵**：`release-offline.env`（零外部依赖，规则抽取+词法检索，FTS5 porter 词干）；`release-enhanced.env`（LLM gpt-5.5 提取/核验/修补（gpt-5.4-mini 兜底档）+ 嵌入 nomic-embed-text，OpenAI/Ollama 兼容端点；**v5 组合**——source-first v10 家族（routing/batches/source-first）保持关闭，因其"独立覆盖"表示依赖活模型无法降档，可用性优先）。同一镜像双形态；`docker compose up -d` 默认 offline，非交互零依赖。
- **LLM 披露**（赛题要求）：

| 用途 | 模型 | 失败行为 |
|---|---|---|
| 分组提取/修补 | gpt-5.5（`MEMORY_EXTRACTION_MODEL`；`MEMORY_LLM_MODEL=gpt-5.4-mini` 为兜底档） | 能力故障（网络/超时/坏 JSON/宕机/分片不可达）→离线正则降档提交（`extraction_offline` 标记） |
| 证据核验 | gpt-5.5（`MEMORY_VERIFICATION_MODEL`） | 协议错一轮修补；核验通道不可用→降档离线方案（离线事实以逐字引证自证，不经语义核验）；**语义拒绝不降级** |
| 擦除独立性/源擦除/状态转移 | gpt-5.5（verification 档） | 能力故障→确定性方案；语义不确定→拒绝 |
| 嵌入 | nomic-embed-text（本地 Ollama） | 降级词法路由（`embedding_lexical` 标记） |

- **接口稳定性**：契约校验器 12 项（health/echo/幂等/读后即查/租户隔离/top-k/三路由/校验/冲突/更新现值/遗忘全路径/邻句保留）全过；422 项单元测试含并发、故障注入、原子回滚、Unicode 边界。
- **预算**：add 115s / search 55s 内部上限，低于赛题 120s/60s；写路径每 user 串行 + 全局限流门。
- **可观测**：`degraded` 事件行（stdout JSON）、检索审计（query/tenant 哈希、阶段 trace、丢弃原因）、模型调用审计文件。

## 五、验证结果（本交付版实测）

1. **单元**：434/434（基座 420 项全保留语义或按新哲学更新断言 + 新增机制测试：题面候选梯、主体降权、聚合卡 10 项、多源佐证 2 项）。
2. **契约**：offline 实例 12/12。
3. **intent v2 全量回归**（2026-09-07 重跑，validation-data/intent-check.mjs）：LoCoMo refined 1,382 题三桶 {CURRENT:1376, HISTORICAL:5, TRAJECTORY:1} 与 round-11 基线逐题一致；MemOps 纵向 134 去重对 OperationTrace 27 + StateTrajectory 5 全部命中 TRAJECTORY、其余 102 对零误路由。重跑发现并修复两处验证后改正则引入的缺陷（"becoming" 词干误报、what-have-I-shared 直连句失配）。
4. **场景回归**（评测形态，无时间戳消息）：
   - 无时间戳 add → 200 且立即可检索；
   - 陈述更新 → 现值 rank-1；历史查询返回包裹模板 `Former … (superseded; current …)`，合成基不打印假日期；
   - `last year` 类相对时间 → `Event date unresolved`（不发明日期）；
   - 题面候选 `60143 or 60148` → 唯一精确命中强制 rank-1；数字近邻无法模糊胜出（单测固化）；
   - 自指查询下用户事实排具名第三方之上（单测固化）；
   - forget → 200 后全检索路径（事实/原文/事件/尾句）不可见；
   - operation 意图查询（"what did I ask you to forget"）→ 事件投影返回操作描述（`MEMORY_EVENT_VIEW=true`）；
   - 复数词干：查询 `hobbies` 命中谓词 `hobby`（FTS5 porter 双侧归一）；
   - **聚合卡端到端**：三次跨会话 add 累积爱好 → 单卡含全部值串且 reflection 事件入账；forget 成员值 → 卡全路径清除零泄漏且**兄弟成员原文零连坐**（成员粒度擦除）；精确复述不复活被忘值；下次内容 add → 从幸存成员干净重建（不含被忘值）；restore 成员后家族卡随下次内容 add 重建；
   - **enhanced + 死 LLM 端点端到端**：health 2xx 且 `models:"degraded"` 如实上报，add 1.6s 降档 200（`extraction_offline` 审计行），search 命中且聚合卡照常产出——基座两轮 0/100 的形态已由测试与场景双固化不再复现。
5. **已知边界**：offline 形态下转述类查询（无词法重叠）召回有限——由 enhanced 形态的嵌入与抽取覆盖；题面候选梯需事实层支持（enhanced 抽出值事实后生效）；source-first v10 表示（独立覆盖）未纳入 release 配置（依赖活模型，可用性自陷）。

## 六、创新性与可扩展性

**创新点**（相对基座与 LMRS 类开源实现）：
1. **意图感知的链仲裁重排**——把"基座混合分无排序信息"变为可操作的排序先验，且降权仅在链内有 confirmed 赢家时做相对分离（状态可见性与排序分离同时成立）；
2. **题面候选四级匹配梯**——针对评测把选项嵌进题干（无 options 字段）的形态，数字近邻只能精确胜出；
3. **能力故障降档提交**——按"评测机不重放"的失败模型重构写入路径，且与三条 fail-closed 契约（退休指令/语义拒绝/续传）划清边界；
4. **合成排序标记不充当日期锚**——无时间戳官方消息下保住生命周期仲裁又不发明时间；
5. **双源擦除 + 独立性豁免**——泄漏与过遗忘的同时防御；
6. **旧值旅行包裹 + as-of 去后继**——呈现层直接对齐 judge 的"旧值率"口径；
7. **确定性聚合卡（反思层）**——一个机制同时服务跨会话列表完备（cat1 MULTI 物化）与 MemOps Reflect 汇总：值排序后原样入卡、随遗忘三重冗余自动清除、降档路径同样产出，零模型依赖；
8. **多源佐证排序信号**——conflict 不靠计数自动消解，复述 ≥2 次的值仅获得相对加成与显式补注，防"两次回声翻转一次更正"的近因陷阱。

**可扩展性**：S1/P2/R3 已在本版落地（聚合卡 + 佐证加成）；后续：LLM 重写聚合卡文案（口语化 Reflect 摘要）；ProfileBundle 预算内常驻（coveragePacking 已覆盖主要收益）；rerank 模型位已留（排序信号分离架构即插即用）；中文谓词族扩展与多租户横向分片（每 user 独立库天然可分片）。
