当前工作区只有赛题规范，没有既有实现或样例评测包，也不是 Git 仓库。本轮新增设计文档，不代表完成了三仓库工程验收。

### 2.1 直接核验的事实

- LoCoMo 固定公开版：10 个 sample、1,382 个问题；每 sample 消息数最小 369、最大 689。category 原始值计数为 `1:213 / 2:299 / 3:68 / 4:802`，未在适配器确认前擅自重命名类别。统计来自 [questions](https://github.com/mem-eval-suite/LoCoMo_refined/blob/887091190789e8d6760e70b9edd696539923dc4f/data/public/questions.jsonl) 和 [conversations](https://github.com/mem-eval-suite/LoCoMo_refined/blob/887091190789e8d6760e70b9edd696539923dc4f/data/public/conversations.jsonl)。
- 上游 [LoCoMo 说明](https://github.com/mem-eval-suite/LoCoMo_refined/blob/887091190789e8d6760e70b9edd696539923dc4f/README.md) 列出了官方 Judge Qwen3-14B；它不说明本赛题固定 Answer 模型具体是什么，不能把 Judge 模型直接当成 Answer 配置。
- MemOps [测试脚本](https://github.com/MemTensor/MemOps/blob/312af65e2c7b6d1b70f062ffa8b4cde32aaf6f35/5-test_operation_metrics.py) 提供检索/记忆对照方法与评测编排，可参考其适配方式，但不能整体搬入 service 绕过 HTTP 契约。
- MemOps [判分脚本](https://github.com/MemTensor/MemOps/blob/312af65e2c7b6d1b70f062ffa8b4cde32aaf6f35/5.5-evaluate_operation_metrics.py) 包含多种题型及诊断规则；不等价于本地规范给出的简短 rubric 示例。

### 2.2 需要保留的上游差异

LoCoMo 的 README 对判分原则作了概述，实际 prompt 存在细分类别规则，不能仅依据概述重写。MemOps 的通用遗忘检查与某些“从当前关系移除”的样本 rubric 存在语义张力。方案采用作用域语义，但最终评分行为仍须用固定脚本实际运行确认；不承诺凭文档解释就一定通过所有 Judge。

三个 MemOps 样本只用于验证存在更新计划陷阱、作用域遗忘、反思线索和噪声等结构，不据此推断所有隐藏题的分布或模式。

## 4. 待赛题方确认的运行条件

| 问题 | 影响 | 当前设计处理 |
| --- | --- | --- |
| CPU/GPU、内存、磁盘、并发 | 本地模型与精确向量检索是否可行 | 先单服务 + 词法回退；按容量实验决定升级 |
| 外部网络及可用模型、额度 | 抽取/embedding/reranker 主配置 | 模型适配层及完全断网最小模式 |
| `/add`、`/search` 的实际 deadline | 是否能同步完成模型调用 | 全请求预算；不默认拿最大超时 |
| 固定 Answer 模型、模板、证据序列化 | 最优证据长度、相对时间表达效果 | 参数化并记录；未确认前仅本地复现 |
| MemOps rubric 到二值分的具体映射 | 正式成绩可比性 | upstream 与 competition Judge 分开 |
| 500+500 的实际抽样、权重与错误处理 | 分母、失败项、正式分数 | 公共数据报告自己的分母，不冒充正式 |
| speaker、caption、timestamp 的转换规则 | 主体绑定与时间真实性 | 记录本地转换假设，做输入敏感性对照 |
| options 元素类型、top_k 边界 | JSON Schema 和客户端策略 | 不将示例擅自提升为类型限制 |
| created_at 的确切语义 | 证据来源时间还是入库时间 | 暂采用首次来源消息 timestamp，内部另存其它时间 |
| 是否乱序/并发灌入同一用户 | 冲突处理、会话顺序 | 同用户串行写入，事件时间和接收顺序分开 |

这些缺口不阻止开始 M0–M2 的独立工程工作；会阻止宣称已通过正式资源和正式评分验证。当前无需为设计阶段预先假设答案。
